## 1. RAII（资源获取即初始化）



### 原理



RAII（Resource Acquisition Is Initialization）是 C++ 最核心的惯用法。核心思想：



- **构造函数获取资源**（内存、文件句柄、锁、网络连接等）

- **析构函数释放资源**

- 利用 C++ 的**确定性析构**（离开作用域时自动调用析构函数），保证资源不泄漏



无论正常返回还是异常抛出，析构函数都会被调用，因此 RAII 是 C++ 异常安全的基石。



### 代码示例



```cpp

#include <memory>

#include <mutex>

#include <fstream>



// 示例1: 智能指针管理堆内存

void example_memory() {

    // 自动管理生命周期，离开作用域自动释放

    auto ptr = std::make_unique<int[]>(1024);

    ptr[0] = 42;

    // 无需 delete，unique_ptr 析构时自动释放

}



// 示例2: lock_guard 管理互斥锁

class Counter {

    mutable std::mutex mtx_;

    int count_ = 0;

public:

    void increment() {

        std::lock_guard<std::mutex> lock(mtx_);  // 构造时加锁

        ++count_;

        // 析构时自动解锁，即使抛异常也安全

    }

};



// 示例3: 自定义 RAII 类

class FileHandle {

    FILE* fp_;

public:

    explicit FileHandle(const char* path, const char* mode)

        : fp_(fopen(path, mode)) {

        if (!fp_) throw std::runtime_error("Cannot open file");

    }

    ~FileHandle() { if (fp_) fclose(fp_); }



    // 禁止拷贝

    FileHandle(const FileHandle&) = delete;

    FileHandle& operator=(const FileHandle&) = delete;



    // 允许移动

    FileHandle(FileHandle&& other) noexcept : fp_(other.fp_) {

        other.fp_ = nullptr;

    }



    FILE* get() const { return fp_; }

};

```



### 适用场景



- 所有需要手动释放的资源：内存、文件、锁、网络连接、数据库句柄

- 替代 try-finally（C++ 没有 finally，靠 RAII）

- 任何需要"配对操作"的地方（open/close, lock/unlock, begin/end）



### 注意事项



- **Rule of 0**：如果类的成员都是 RAII 类型（智能指针等），不需要写析构/拷贝/移动

- **Rule of 5**：如果必须自定义析构函数，也要定义拷贝构造、拷贝赋值、移动构造、移动赋值

- 避免裸 `new`/`delete`，用 `make_unique`/`make_shared`

## 2. Observer（观察者模式）



### 原理



定义对象间的**一对多依赖关系**：当一个对象（Subject）状态变化时，所有依赖它的对象（Observer）都会收到通知并自动更新。



核心组件：

- **Subject（被观察者）**：维护观察者列表，状态变化时通知所有观察者

- **Observer（观察者）**：定义更新接口，收到通知后执行相应操作



### 代码示例



```cpp

#include <functional>

#include <vector>

#include <string>

#include <iostream>



// 现代 C++ 风格：用 std::function 做回调（轻量观察者）

class EventEmitter {

public:

    using Callback = std::function<void(const std::string&)>;



    // 注册观察者，返回 ID 用于取消注册

    size_t on(Callback cb) {

        listeners_.push_back({next_id_, std::move(cb)});

        return next_id_++;

    }



    // 取消注册

    void off(size_t id) {

        listeners_.erase(

            std::remove_if(listeners_.begin(), listeners_.end(),

                [id](const auto& p) { return p.first == id; }),

            listeners_.end());

    }



    // 触发事件，通知所有观察者

    void emit(const std::string& event) {

        for (auto& [id, cb] : listeners_) {

            cb(event);

        }

    }



private:

    std::vector<std::pair<size_t, Callback>> listeners_;

    size_t next_id_ = 0;

};



// 使用

void demo() {

    EventEmitter emitter;



    auto id1 = emitter.on([](const std::string& msg) {

        std::cout << "Logger: " << msg << "\n";

    });



    auto id2 = emitter.on([](const std::string& msg) {

        std::cout << "UI Update: " << msg << "\n";

    });



    emitter.emit("user_login");   // 两个观察者都会收到

    emitter.off(id1);              // 取消 Logger

    emitter.emit("user_logout");   // 只有 UI 收到

}

```



### 经典面向对象版本



```cpp

class IObserver {

public:

    virtual ~IObserver() = default;

    virtual void onNotify(int event_type, void* data) = 0;

};



class Subject {

    std::vector<IObserver*> observers_;

public:

    void attach(IObserver* obs) { observers_.push_back(obs); }

    void detach(IObserver* obs) {

        observers_.erase(std::remove(observers_.begin(), observers_.end(), obs),

                         observers_.end());

    }

protected:

    void notify(int event_type, void* data = nullptr) {

        for (auto* obs : observers_) obs->onNotify(event_type, data);

    }

};

```



### 适用场景



- GUI 事件系统（按钮点击、窗口关闭）

- Qt 的信号与槽机制

- 消息总线 / 事件总线

- 数据绑定（Model 变化自动刷新 View）

- 游戏中的成就系统（监听各种游戏事件）



### 注意事项



- **生命周期管理**：观察者被销毁前必须取消注册，否则悬空指针

- **线程安全**：多线程环境需要加锁保护观察者列表

- **通知顺序**：不要依赖观察者被通知的顺序

- 使用 `weak_ptr` 可以自动检测观察者是否已销毁

## 3. Factory（工厂模式）



### 原理



将**对象的创建逻辑**与使用逻辑分离。调用者不需要知道具体创建哪个子类，只需要通过工厂接口获取对象。



三种变体：

- **简单工厂**：一个函数根据参数创建不同对象

- **工厂方法**：每个子类有自己的工厂

- **抽象工厂**：创建一组相关对象的工厂族



### 代码示例



```cpp

#include <memory>

#include <string>

#include <unordered_map>

#include <functional>



// --- 简单工厂 ---

class Shape {

public:

    virtual ~Shape() = default;

    virtual double area() const = 0;

    virtual std::string name() const = 0;

};



class Circle : public Shape {

    double radius_;

public:

    explicit Circle(double r) : radius_(r) {}

    double area() const override { return 3.14159 * radius_ * radius_; }

    std::string name() const override { return "Circle"; }

};



class Rectangle : public Shape {

    double w_, h_;

public:

    Rectangle(double w, double h) : w_(w), h_(h) {}

    double area() const override { return w_ * h_; }

    std::string name() const override { return "Rectangle"; }

};



// 简单工厂函数

std::unique_ptr<Shape> createShape(const std::string& type) {

    if (type == "circle")    return std::make_unique<Circle>(1.0);

    if (type == "rectangle") return std::make_unique<Rectangle>(2.0, 3.0);

    return nullptr;

}



// --- 注册式工厂（更灵活） ---

class ShapeFactory {

public:

    using Creator = std::function<std::unique_ptr<Shape>()>;



    static ShapeFactory& instance() {

        static ShapeFactory inst;

        return inst;

    }



    void registerShape(const std::string& name, Creator creator) {

        creators_[name] = std::move(creator);

    }



    std::unique_ptr<Shape> create(const std::string& name) const {

        auto it = creators_.find(name);

        if (it == creators_.end()) return nullptr;

        return it->second();

    }



private:

    std::unordered_map<std::string, Creator> creators_;

};



// 自动注册宏（可选）

#define REGISTER_SHAPE(Name, Creator) \

    static bool _reg_##Name = [] { \

        ShapeFactory::instance().registerShape(#Name, Creator); \

        return true; \

    }()

```



### 适用场景



- 插件系统（根据配置加载不同模块）

- 协议解析（根据消息类型创建对应 handler）

- 序列化/反序列化（根据类型标识恢复对象）

- 数据库驱动选择（MySQL / PostgreSQL / SQLite）



### 注意事项



- 简单工厂违反开闭原则（新增类型需修改工厂函数）

- 注册式工厂更灵活，支持动态扩展

- 返回 `unique_ptr` 而非裸指针，保证 RAII

## 4. Strategy（策略模式）



### 原理



定义一系列**可互换的算法**，把每个算法封装成独立的对象，使得算法可以在运行时切换，而不影响使用算法的客户端代码。



在现代 C++ 中，由于有 lambda 和 `std::function`，策略模式变得极其简洁。



### 代码示例



```cpp

#include <algorithm>

#include <vector>

#include <functional>

#include <iostream>



// --- 方式1: 模板参数（编译期策略，零开销） ---

template<typename SortPolicy>

class DataProcessor {

    std::vector<int> data_;

public:

    void addData(int val) { data_.push_back(val); }



    void process() {

        SortPolicy{}(data_);  // 调用策略

    }



    void print() const {

        for (int x : data_) std::cout << x << " ";

        std::cout << "\n";

    }

};



struct AscendingSort {

    void operator()(std::vector<int>& v) {

        std::sort(v.begin(), v.end());

    }

};



struct DescendingSort {

    void operator()(std::vector<int>& v) {

        std::sort(v.begin(), v.end(), std::greater<>{});

    }

};



// --- 方式2: std::function（运行时策略，灵活） ---

class Compressor {

public:

    using CompressFunc = std::function<std::string(const std::string&)>;



    void setStrategy(CompressFunc strategy) {

        strategy_ = std::move(strategy);

    }



    std::string compress(const std::string& data) {

        if (!strategy_) throw std::logic_error("No strategy set");

        return strategy_(data);

    }



private:

    CompressFunc strategy_;

};



// 使用

void demo() {

    Compressor c;



    // 策略1: gzip

    c.setStrategy([](const std::string& data) {

        return "gzip(" + data + ")";

    });

    std::cout << c.compress("hello") << "\n";



    // 策略2: lz4

    c.setStrategy([](const std::string& data) {

        return "lz4(" + data + ")";

    });

    std::cout << c.compress("hello") << "\n";

}

```



### STL 中的策略模式



```cpp

// std::sort 的比较器就是策略

std::sort(v.begin(), v.end(), std::less<>{});       // 升序策略

std::sort(v.begin(), v.end(), std::greater<>{});    // 降序策略



// std::map 的比较器也是策略

std::map<std::string, int, std::greater<>> desc_map;  // 降序 map



// std::allocator 是内存分配策略

std::vector<int, MyAllocator<int>> v;

```



### 适用场景



- 排序/搜索算法可切换

- 日志输出策略（控制台 / 文件 / 网络）

- 压缩/加密算法选择

- 价格计算策略（正常价 / VIP 价 / 促销价）

- 网络重试策略（指数退避 / 固定间隔）



### 注意事项



- 编译期策略（模板）：零开销，但不能运行时切换

- 运行时策略（std::function）：灵活，但有一次间接调用开销

- 大多数情况下 lambda + std::function 足够，不需要定义接口类

## 5. Singleton（单例模式）



### 原理



确保一个类**只有一个实例**，并提供全局访问点。在 C++11 之后，利用局部静态变量的线程安全初始化（Meyers' Singleton），实现变得极其简洁。



### 代码示例



```cpp

#include <string>

#include <mutex>

#include <fstream>



// --- Meyers' Singleton（推荐，C++11 线程安全） ---

class Config {

public:

    static Config& instance() {

        static Config inst;  // C++11 保证线程安全的静态初始化

        return inst;

    }



    std::string get(const std::string& key) const {

        // 查找配置...

        return "";

    }



    void load(const std::string& path) {

        // 加载配置文件...

    }



    // 禁止拷贝和移动

    Config(const Config&) = delete;

    Config& operator=(const Config&) = delete;

    Config(Config&&) = delete;

    Config& operator=(Config&&) = delete;



private:

    Config() { /* 初始化 */ }

    ~Config() = default;

};



// 使用

void demo() {

    Config::instance().load("app.conf");

    auto value = Config::instance().get("db_host");

}



// --- 带模板的通用单例（可选） ---

template<typename T>

class Singleton {

public:

    static T& instance() {

        static T inst;

        return inst;

    }

protected:

    Singleton() = default;

    ~Singleton() = default;

    Singleton(const Singleton&) = delete;

    Singleton& operator=(const Singleton&) = delete;

};



class Logger : public Singleton<Logger> {

    friend class Singleton<Logger>;  // 允许基类访问私有构造

    Logger() = default;

public:

    void log(const std::string& msg) { /* ... */ }

};

```



### 适用场景



- 配置管理器

- 日志系统

- 数据库连接池

- 线程池

- 硬件设备管理器



### 注意事项



- **不要滥用**：单例本质是全局状态，过度使用导致耦合和测试困难

- **销毁顺序**：多个单例之间有依赖时，注意 static 变量的销毁顺序

- **可测试性**：考虑提供 `reset()` 接口或使用依赖注入替代

- 如果只是需要"全局访问"，不一定需要单例，传参或依赖注入更好

## 6. State（状态机模式）



### 原理



允许对象在其**内部状态改变时改变行为**，对象看起来好像修改了它的类。把每个状态的行为封装到独立的类/函数中，状态转换变得清晰可控。



### 代码示例



```cpp

#include <iostream>

#include <memory>

#include <string>

#include <variant>

#include <functional>



// --- 方式1: 枚举 + switch（简单直接） ---

class TcpConnection {

public:

    enum class State { Closed, Listening, SynSent, Established, CloseWait };



    void open() {

        switch (state_) {

            case State::Closed:

                state_ = State::Listening;

                std::cout << "Listening...\n";

                break;

            default:

                std::cout << "Cannot open in current state\n";

                break;

        }

    }



    void connect() {

        switch (state_) {

            case State::Listening:

                state_ = State::SynSent;

                std::cout << "SYN sent...\n";

                break;

            case State::SynSent:

                state_ = State::Established;

                std::cout << "Connection established!\n";

                break;

            default:

                std::cout << "Invalid transition\n";

                break;

        }

    }



    void close() {

        state_ = State::Closed;

        std::cout << "Connection closed\n";

    }



    State state() const { return state_; }



private:

    State state_ = State::Closed;

};



// --- 方式2: std::variant（类型安全状态机，C++17） ---

struct Idle {};

struct Running { int progress = 0; };

struct Paused { int progress = 0; };

struct Finished { std::string result; };



using TaskState = std::variant<Idle, Running, Paused, Finished>;



class Task {

    TaskState state_ = Idle{};

public:

    void start() {

        if (std::holds_alternative<Idle>(state_)) {

            state_ = Running{0};

            std::cout << "Task started\n";

        }

    }



    void pause() {

        if (auto* running = std::get_if<Running>(&state_)) {

            state_ = Paused{running->progress};

            std::cout << "Task paused at " << running->progress << "%\n";

        }

    }



    void resume() {

        if (auto* paused = std::get_if<Paused>(&state_)) {

            state_ = Running{paused->progress};

            std::cout << "Task resumed from " << paused->progress << "%\n";

        }

    }



    void complete(const std::string& result) {

        if (std::holds_alternative<Running>(state_)) {

            state_ = Finished{result};

            std::cout << "Task finished: " << result << "\n";

        }

    }



    // 用 std::visit 获取状态描述

    std::string describe() const {

        return std::visit([](const auto& s) -> std::string {

            using T = std::decay_t<decltype(s)>;

            if constexpr (std::is_same_v<T, Idle>)     return "Idle";

            if constexpr (std::is_same_v<T, Running>)  return "Running " + std::to_string(s.progress) + "%";

            if constexpr (std::is_same_v<T, Paused>)   return "Paused at " + std::to_string(s.progress) + "%";

            if constexpr (std::is_same_v<T, Finished>) return "Done: " + s.result;

        }, state_);

    }

};

```



### 适用场景



- 网络协议实现（TCP 状态机、HTTP 解析器）

- 游戏角色 AI（待机 -> 巡逻 -> 追击 -> 攻击）

- UI 交互状态（空闲 -> 拖拽 -> 释放）

- 工作流引擎（审批流程的各个阶段）

- 编译器前端（词法分析状态机）



### 注意事项



- 状态少（<5）时用枚举 + switch 足够

- 状态多或转换复杂时，用 variant 或状态类

- 确保**非法状态转换**有明确的错误处理

- 考虑使用状态转换表（table-driven）让规则可配置

## 7. Thread Pool（线程池）



### 原理



预先创建一组工作线程，通过**任务队列**接收任务。避免频繁创建/销毁线程的开销，控制并发度，提高资源利用率。



核心组件：

- **任务队列**：线程安全的 FIFO 队列

- **工作线程**：从队列取任务并执行

- **提交接口**：用户将任务放入队列



### 代码示例



```cpp

#include <thread>

#include <mutex>

#include <condition_variable>

#include <queue>

#include <functional>

#include <vector>

#include <future>



class ThreadPool {

public:

    explicit ThreadPool(size_t num_threads = std::thread::hardware_concurrency()) {

        for (size_t i = 0; i < num_threads; ++i) {

            workers_.emplace_back([this] {

                while (true) {

                    std::function<void()> task;

                    {

                        std::unique_lock<std::mutex> lock(mutex_);

                        cv_.wait(lock, [this] {

                            return stop_ || !tasks_.empty();

                        });

                        if (stop_ && tasks_.empty()) return;

                        task = std::move(tasks_.front());

                        tasks_.pop();

                    }

                    task();  // 执行任务

                }

            });

        }

    }



    ~ThreadPool() {

        {

            std::lock_guard<std::mutex> lock(mutex_);

            stop_ = true;

        }

        cv_.notify_all();

        for (auto& worker : workers_) {

            worker.join();

        }

    }



    // 提交任务，返回 future 获取结果

    template<typename F, typename... Args>

    auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))> {

        using ReturnType = decltype(f(args...));

        auto task = std::make_shared<std::packaged_task<ReturnType()>>(

            std::bind(std::forward<F>(f), std::forward<Args>(args)...)

        );

        auto future = task->get_future();

        {

            std::lock_guard<std::mutex> lock(mutex_);

            if (stop_) throw std::runtime_error("ThreadPool is stopped");

            tasks_.emplace([task]() { (*task)(); });

        }

        cv_.notify_one();

        return future;

    }



private:

    std::vector<std::thread> workers_;

    std::queue<std::function<void()>> tasks_;

    std::mutex mutex_;

    std::condition_variable cv_;

    bool stop_ = false;

};



// 使用

void demo() {

    ThreadPool pool(4);



    // 提交任务

    auto future1 = pool.submit([] { return 42; });

    auto future2 = pool.submit([](int a, int b) { return a + b; }, 3, 4);



    std::cout << future1.get() << "\n";  // 42

    std::cout << future2.get() << "\n";  // 7

}

```



### 适用场景



- Web 服务器请求处理

- 并行文件处理（批量图片转换）

- 数据库查询并发执行

- 游戏服务器的逻辑线程池

- 任何 CPU 密集型并行计算



### 注意事项



- 线程数通常设为 `hardware_concurrency()`（CPU 核数）

- I/O 密集型任务可适当增加线程数

- 避免任务中再向同一线程池提交任务（可能死锁）

- C++20 可以考虑用 `std::jthread` 简化

## 8. Reactor（反应器模式）



### 原理



Reactor 是一种**事件驱动的 I/O 处理模式**：



1. 一个事件循环（event loop）运行在主线程

2. 使用 I/O 多路复用（epoll/kqueue/select）监听多个文件描述符

3. 当某个 fd 就绪（可读/可写）时，分发给对应的事件处理器（handler）



关键优势：**单线程管理海量连接**，避免为每个连接创建线程的开销。



### 代码示例



```cpp

#include <sys/epoll.h>

#include <unistd.h>

#include <functional>

#include <unordered_map>

#include <stdexcept>



// 简化版 Reactor（Linux epoll）

class Reactor {

public:

    using EventHandler = std::function<void(int fd, uint32_t events)>;



    Reactor() {

        epoll_fd_ = epoll_create1(0);

        if (epoll_fd_ < 0) throw std::runtime_error("epoll_create failed");

    }



    ~Reactor() { close(epoll_fd_); }



    // 注册文件描述符和对应的处理器

    void registerHandler(int fd, uint32_t events, EventHandler handler) {

        epoll_event ev{};

        ev.events = events;

        ev.data.fd = fd;

        epoll_ctl(epoll_fd_, EPOLL_CTL_ADD, fd, &ev);

        handlers_[fd] = std::move(handler);

    }



    // 移除处理器

    void removeHandler(int fd) {

        epoll_ctl(epoll_fd_, EPOLL_CTL_DEL, fd, nullptr);

        handlers_.erase(fd);

    }



    // 运行事件循环

    void run() {

        constexpr int MAX_EVENTS = 1024;

        epoll_event events[MAX_EVENTS];



        running_ = true;

        while (running_) {

            int n = epoll_wait(epoll_fd_, events, MAX_EVENTS, -1);

            for (int i = 0; i < n; ++i) {

                int fd = events[i].data.fd;

                auto it = handlers_.find(fd);

                if (it != handlers_.end()) {

                    it->second(fd, events[i].events);

                }

            }

        }

    }



    void stop() { running_ = false; }



private:

    int epoll_fd_;

    std::unordered_map<int, EventHandler> handlers_;

    bool running_ = false;

};



// 使用示例（TCP 服务器）

/*

    Reactor reactor;



    // 注册监听 socket

    reactor.registerHandler(listen_fd, EPOLLIN, [&](int fd, uint32_t) {

        int client_fd = accept(fd, nullptr, nullptr);

        // 注册新客户端

        reactor.registerHandler(client_fd, EPOLLIN, handleClient);

    });



    reactor.run();

*/

```



### 变体



| 模型 | 描述 | 典型应用 |
| --- | --- | --- |
| 单 Reactor 单线程 | 一个线程做所有事 | Redis (6.0 前) |
| 单 Reactor 多线程 | 主线程 accept，工作线程处理业务 | 简单服务器 |
| 多 Reactor 多线程 | 主 Reactor accept，子 Reactor 处理 I/O | Nginx, Muduo, Netty |



### 适用场景



- 高性能网络服务器

- 中间件（消息队列、代理）

- 游戏服务器

- 数据库服务器



### 注意事项



- handler 中不能做阻塞操作（否则卡住整个事件循环）

- 计算密集任务应提交到线程池

- Linux 用 epoll，macOS 用 kqueue，Windows 用 IOCP（对应 Proactor）

- 推荐使用成熟库（libevent, libev, Boost.Asio）而非自己实现

## 9. CRTP（奇异递归模板模式）



### 原理



CRTP（Curiously Recurring Template Pattern）：基类是一个模板，**派生类把自身作为模板参数传给基类**。实现**编译期多态**，无虚函数表开销。



```

class Derived : public Base<Derived> { ... }

```



基类可以通过 `static_cast<Derived*>(this)` 调用派生类的方法，完全在编译期解析，零运行时开销。



### 代码示例



```cpp

#include <iostream>

#include <chrono>



// --- 示例1: 编译期多态 ---

template<typename Derived>

class Shape {

public:

    double area() const {

        // 编译期调用派生类方法，无虚函数开销

        return static_cast<const Derived*>(this)->areaImpl();

    }



    void draw() const {

        static_cast<const Derived*>(this)->drawImpl();

    }

};



class Circle : public Shape<Circle> {

    double radius_;

public:

    explicit Circle(double r) : radius_(r) {}

    double areaImpl() const { return 3.14159 * radius_ * radius_; }

    void drawImpl() const { std::cout << "Drawing circle r=" << radius_ << "\n"; }

};



class Square : public Shape<Square> {

    double side_;

public:

    explicit Square(double s) : side_(s) {}

    double areaImpl() const { return side_ * side_; }

    void drawImpl() const { std::cout << "Drawing square s=" << side_ << "\n"; }

};



// 模板函数接受任何 Shape

template<typename T>

void printArea(const Shape<T>& shape) {

    std::cout << "Area: " << shape.area() << "\n";

}



// --- 示例2: Mixin 功能注入 ---

template<typename Derived>

class Printable {

public:

    void print() const {

        const auto& self = static_cast<const Derived&>(*this);

        std::cout << self.toString() << "\n";

    }

};



template<typename Derived>

class Comparable {

public:

    bool operator==(const Derived& other) const {

        const auto& self = static_cast<const Derived&>(*this);

        return self.compareTo(other) == 0;

    }

    bool operator<(const Derived& other) const {

        const auto& self = static_cast<const Derived&>(*this);

        return self.compareTo(other) < 0;

    }

};



class Point : public Printable<Point>, public Comparable<Point> {

    int x_, y_;

public:

    Point(int x, int y) : x_(x), y_(y) {}

    std::string toString() const {

        return "(" + std::to_string(x_) + ", " + std::to_string(y_) + ")";

    }

    int compareTo(const Point& other) const {

        if (x_ != other.x_) return x_ - other.x_;

        return y_ - other.y_;

    }

};



// --- 示例3: std::enable_shared_from_this（STL中的CRTP） ---

class Session : public std::enable_shared_from_this<Session> {

public:

    void start() {

        // 安全地获取指向自身的 shared_ptr

        auto self = shared_from_this();

        // 把 self 传给异步回调...

    }

};

```



### 适用场景



- 高性能数值计算库（Eigen 矩阵）

- 需要"静态多态"的场景（替代虚函数）

- Mixin 模式（给类注入通用功能）

- `std::enable_shared_from_this`

- 编译期接口约束



### 注意事项



- 不能实现运行时多态（不能用基类指针指向不同派生类）

- 代码会被膨胀（每个 Derived 都生成独立的基类实例化）

- 错误信息可能很难读（模板报错）

- 适合库开发者，普通业务代码中较少直接使用

## 10. pimpl（编译防火墙）



### 原理



pimpl（Pointer to Implementation）也叫**编译防火墙**或 **Cheshire Cat**：



- 在头文件中只声明一个指向实现类的指针

- 实现细节全部放在 .cpp 文件中

- 修改实现不需要重新编译依赖该头文件的代码



解决的问题：C++ 头文件修改会导致所有 include 它的文件重新编译（编译依赖传播）。



### 代码示例



```cpp

// === widget.h ===（对外暴露的头文件）

#pragma once

#include <memory>

#include <string>



class Widget {

public:

    Widget();

    ~Widget();                          // 必须声明，因为 Impl 不完整



    // 移动操作（可选但推荐）

    Widget(Widget&& other) noexcept;

    Widget& operator=(Widget&& other) noexcept;



    // 禁止拷贝（或自定义深拷贝）

    Widget(const Widget&) = delete;

    Widget& operator=(const Widget&) = delete;



    // 公共接口

    void setName(const std::string& name);

    std::string getName() const;

    void doWork();



private:

    struct Impl;                        // 前置声明，不暴露任何实现细节

    std::unique_ptr<Impl> pimpl_;       // 指向实现的指针

};





// === widget.cpp ===（实现文件）

#include "widget.h"

#include <iostream>

#include <vector>

#include <algorithm>

// 这里可以 include 任何重型头文件，不会传播到使用者



struct Widget::Impl {

    std::string name;

    std::vector<int> data;

    // 可以包含任何复杂的私有成员

    // 修改这里不需要重新编译包含 widget.h 的文件



    void internalHelper() {

        std::sort(data.begin(), data.end());

    }

};



Widget::Widget() : pimpl_(std::make_unique<Impl>()) {}

Widget::~Widget() = default;  // 必须在 .cpp 中定义（Impl 完整类型）

Widget::Widget(Widget&&) noexcept = default;

Widget& Widget::operator=(Widget&&) noexcept = default;



void Widget::setName(const std::string& name) {

    pimpl_->name = name;

}



std::string Widget::getName() const {

    return pimpl_->name;

}



void Widget::doWork() {

    pimpl_->internalHelper();

    std::cout << "Working on " << pimpl_->name << "\n";

}

```



### 适用场景



- 大型项目减少编译时间

- 库的公共 API 头文件（保持二进制兼容）

- 隐藏第三方依赖（用户不需要安装你依赖的库的头文件）

- 跨 DLL 边界保持 ABI 稳定



### 注意事项



- 有一次额外的指针间接访问开销（通常可忽略）

- 不能内联实现类的方法

- 析构函数必须在 .cpp 中定义（`unique_ptr` 需要完整类型）

- 移动语义也需要在 .cpp 中定义

- 如果需要拷贝，需手动实现深拷贝

| # | 模式 | 层面 | 核心价值 | 复杂度 |
| --- | --- | --- | --- | --- |
| 1 | RAII | 惯用法 | 资源安全，异常安全 | 低 |

| 6 | State | 行为模式 | 状态驱动行为 | 中 |
| 7 | Thread Pool | 并发模式 | 控制并发度，复用线程 | 中-高 |
| 8 | Reactor | 并发模式 | 高并发 I/O | 高 |
| 9 | CRTP | C++ 惯用法 | 编译期多态，零开销 | 中 |
| 10 | pimpl | C++ 惯用法 | 减少编译依赖 | 低 |

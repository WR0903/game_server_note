## C++ 多线程锁总结（C++11/14/17）

### 一、核心锁类型

#### 1. `std::mutex` — 基础互斥锁（C++11）

- 最基本的锁，同一时刻只有一个线程可持有

- **不可递归**：同一线程重复加锁会死锁

```cpp
std::mutex mtx;
mtx.lock();       // 加锁（阻塞等待）
mtx.unlock();     // 解锁
mtx.try_lock();   // 尝试加锁（非阻塞，失败返回 false）
```

> ⚠️ **绝不建议直接用 `lock()/unlock()`**，应搭配 RAII 锁守卫使用

---

#### 2. `std::recursive_mutex` — 递归互斥锁（C++11）

- 同一线程可多次加锁，需同等次数解锁

- **适用场景**：递归函数中需要加锁、类方法互相调用且都需加锁

```cpp
std::recursive_mutex rmtx;
void recursive_func(int depth) {
    rmtx.lock();     // 同一线程可重复加锁，不会死锁
    if (depth > 0) recursive_func(depth - 1);
    rmtx.unlock();
}
```

> ⚠️ 注意：过度使用递归锁可能是设计问题，优先重构避免递归加锁

---

#### 3. `std::timed_mutex` — 定时互斥锁（C++11）

- 支持**超时**的互斥锁

- `try_lock_for(duration)` — 等待指定时长

- `try_lock_until(time_point)` — 等待到指定时间点

```cpp
std::timed_mutex tmtx;
if (tmtx.try_lock_for(std::chrono::milliseconds(100))) {
    // 100ms 内成功获取锁
    tmtx.unlock();
} else {
    // 超时未获取
}
```

---

#### 4. `std::recursive_timed_mutex` — 递归定时锁（C++11）

- 递归锁 + 超时能力的组合

- 同一线程可重复加锁，且支持超时等待

---

### 二、RAII 锁守卫（C++11）— **最常用**

直接用 `lock()/unlock()` 容易出错（忘记解锁、异常时未解锁），RAII 守卫自动管理生命周期。

#### 1. `std::lock_guard` — 最简单（C++11）

- 构造时加锁，析构时解锁

- **不可手动解锁**，生命周期与作用域绑定

- 最轻量，无额外开销

```cpp
std::mutex mtx;
{
    std::lock_guard<std::mutex> lg(mtx);  // 加锁
    // ... 临界区操作
}  // 自动解锁（离开作用域）
```

---

#### 2. `std::unique_lock` — 最灵活（C++11）

- 可延迟加锁、提前解锁、转移所有权（可移动）

- 比 `lock_guard` 略有开销，但功能更丰富

```cpp
std::mutex mtx;
// 延迟加锁
std::unique_lock<std::mutex> ul(mtx, std::defer_lock);
ul.lock();        // 手动加锁
ul.unlock();      // 手动解锁（可提前解锁）
ul.lock();        // 可再次加锁
// 尝试加锁
std::unique_lock<std::mutex> ul(mtx, std::try_to_lock);
if (ul.owns_lock()) { /* 成功 */ }
// 定时加锁（需 timed_mutex）
std::unique_lock<std::timed_mutex> ul(tmtx, std::chrono::milliseconds(100));
// 移动语义
std::unique_lock<std::mutex> ul2 = std::move(ul);  // 所有权转移
```

**`unique_lock` 常用构造标签：**

| 标签 | 行为 |
| --- | --- |
| `std::defer_lock` | 不加锁，稍后手动加 |
| `std::try_to_lock` | 尝试加锁，失败不阻塞 |
| `std::adopt_lock` | 假设已加锁，只管理解锁 |

---

### 三、多锁管理（C++11）

#### 1. `std::lock()` — 同时加多个锁，避免死锁

- 一次性获取多个锁，内部使用**避免死锁算法**

- 如果获取部分锁失败，会释放已获取的锁再重试

```cpp
std::mutex mtx1, mtx2;
std::lock(mtx1, mtx2);  // 同时获取两个锁，不会死锁
std::lock_guard<std::mutex> lg1(mtx1, std::adopt_lock);
std::lock_guard<std::mutex> lg2(mtx2, std::adopt_lock);
// 临界区操作，两个锁都会在作用域结束时释放
```

#### 2. `std::try_lock()` — 尝试同时加多个锁

- 非阻塞版本，返回第一个失败的锁索引，成功返回 -1

- 获取部分成功时会释放已获取的锁

```cpp
std::mutex mtx1, mtx2, mtx3;
int result = std::try_lock(mtx1, mtx2, mtx3);
// result = -1: 全部成功
// result = 0:  mtx1 失败（mtx2, mtx3 未尝试）
// result = 1:  mtx1 成功，mtx2 失败（mtx1 已释放）
```

#### 3. `std::scoped_lock` — 多锁 RAII 守卫（**C++17**）

- C++17 新增，是 `std::lock_guard` 的多锁版本

- 构造时调用 `std::lock()` 加多个锁，析构时全部解锁

- **单锁场景等同 `lock_guard`，推荐替代 `lock_guard`**

```cpp
std::mutex mtx1, mtx2;
{
    std::scoped_lock sl(mtx1, mtx2);  // 同时获取两个锁，无死锁风险
    // 临界区
}  // 自动释放两个锁
// 单锁也行（C++17 推荐用 scoped_lock 替代 lock_guard）
std::scoped_lock sl(mtx);  // 等同 lock_guard<mutex>
```

---

### 四、条件变量（C++11）

#### `std::condition_variable` + `std::condition_variable_any`

- 必须搭配 `unique_lock<mutex>` 使用

- `wait()` — 阻塞等待通知（同时解锁，被通知时重新加锁）

- `wait_for()` / `wait_until()` — 超时等待

- `notify_one()` — 通知一个等待线程

- `notify_all()` — 通知所有等待线程

```cpp
std::mutex mtx;
std::condition_variable cv;
bool ready = false;
// 等待线程
std::unique_lock<std::mutex> ul(mtx);
cv.wait(ul, []{ return ready; });  // 带 predicate 的 wait（避免虚假唤醒）
// 通知线程
{
    std::lock_guard<std::mutex> lg(mtx);
    ready = true;
}
cv.notify_one();  // 或 cv.notify_all()
```

---

### 五、C++14 新增

| 特性 | 说明 |
| --- | --- |
| `std::shared_timed_mutex` | 共享 timed mutex，读写锁带超时 |
| `std::shared_lock` 支持定时 | `shared_lock` 可搭配 `shared_timed_mutex` |

C++14 没有新增基础锁类型，主要补充了 `shared_timed_mutex` 的定时能力。

---

### 六、C++17 新增

| 特性 | 说明 |
| --- | --- |
| `std::scoped_lock` | 多锁 RAII 守卫，替代手动 `std::lock()` + `lock_guard` |
| `std::shared_mutex` | 无超时的共享互斥锁（读写锁） |

#### 读写锁 — `shared_mutex` / `shared_timed_mutex`

| 版本 | 类型 | 特性 |
| --- | --- | --- |
| C++14 | `shared_timed_mutex` | 读写锁 + 超时 |
| C++17 | `shared_mutex` | 读写锁（无超时，更轻量） |

```cpp
std::shared_mutex smtx;  // C++17
// 读操作 — 共享锁（多个读者可并发）
std::shared_lock<std::shared_mutex> sl(smtx);  // 多线程可同时持有
// 写操作 — 独占锁
std::unique_lock<std::shared_mutex> ul(smtx);  // 独占，排斥所有读者和写者
```

### 八、选择指南

| 场景 | 推荐 |
| --- | --- |
| 简单临界区 | `scoped_lock`（C++17）或 `lock_guard` |
| 需要延迟/提前解锁 | `unique_lock` |
| 需要条件变量等待 | `unique_lock` + `condition_variable` |
| 多个锁同时获取 | `scoped_lock`（C++17），或 `std::lock()` + `adopt_lock` |
| 读写场景（读多写少） | `shared_mutex` + `shared_lock`(读) + `unique_lock`(写) |
| 递归加锁 | `recursive_mutex`（但优先重构避免） |
| 需要超时等待 | `timed_mutex` / `shared_timed_mutex` |

---

### 九、最佳实践

1. **优先用 RAII 守卫**，绝不手动 `lock()/unlock()`

2. **C++17 优先用 `scoped_lock`**，它同时替代 `lock_guard` 和手动 `std::lock()`

3. **尽量减少锁的持有时间** — 临界区代码尽量短

4. **多锁用 `scoped_lock` 或 `std::lock()`**，不要逐个加锁（死锁风险）

5. **优先重构而非用递归锁** — 递归锁往往意味着设计问题

6. **读写场景用 `shared_mutex`** — 读多写少时性能显著提升

7. **条件变量 `wait()` 必须带 predicate** — 防止虚假唤醒

8. **锁顺序保持一致** — 多线程获取多个锁时，顺序必须一致
